# 公网照片识别

## 功能与当前验收边界

HTTPS 工作台直接拍照或选择相册照片，经腾讯云 TokenHub 图片理解生成待确认食材。普通访客无需 WorkBuddy、本地连接或模型安装。原 `http://127.0.0.1:43117/` 且带工作区标记的入口保留 WorkBuddy；单文件 HTML 不提供云端照片服务。

代码、错误回退、持久化限额与自动测试可以独立验证，但**只有配置可用的 TokenHub API Key 并实拍测试后，才能宣布照片识别已上线可用**。状态接口只检查配置；它不代替模型权限、数据库迁移和实拍验收。

公网做菜使用完整的 70 道预设家常做法；只依赖本地连接的可选 WorkBuddy 重写入口保留在本地版，不在公网显示失效按钮。

## 维护者配置

1. 在 [TokenHub 控制台](https://console.cloud.tencent.com/tokenhub/) 开通服务，确认 `hy-vision-2.0-instruct` 有可用额度。是否购买或开启后付费由维护者决定。
2. 在 [API Key 管理](https://console.cloud.tencent.com/tokenhub/apikey) 创建广州地域密钥，限制到该视觉模型。**不是语音服务的 SecretId/SecretKey**。
3. 本地 `.env` 与 Sites 服务端分别配置 `TOKENHUB_API_KEY`（secret）、`KITCHEN_PHOTO_ENABLED=1`、`KITCHEN_PHOTO_DAILY_LIMIT=100`。不要使用 `VITE_` / `NEXT_PUBLIC_` 前缀，不把密钥写进源码或 HTML。
4. 沿用逻辑 D1 绑定 `VOICE_LIMITS`，新迁移 `drizzle/0001_photo_usage_limits.sql` 创建独立的 `photo_usage` 表。Sites 在发布前应用迁移，旧语音表及计数不修改。
5. 配置完成后发布新版，再验收 HTTPS 上的实际照片识别。没有配置时关闭照片调用，并保留手动录入。

## 数据与操作边界

- 文件先在浏览器解码、缩放到最长边 1600 像素、重新编码 JPEG（不带原始 EXIF / GPS），最大上传 1.5 MB。选择照片不会上传；必须点击“开始识别”。源文件上限 12 MB，支持浏览器可解码的 JPG/PNG/WebP；HEIC/HEIF 取决于浏览器原生解码能力，不能解码时明确提示换图。
- 只接受同源 JPEG 请求，检查大小、JPEG 帧尺寸及来源；不接受远程图片 URL、客户端模型名、提示词、库存或识别服务地址。
- 服务端固定请求 `https://tokenhub.tencentmaas.com/v1/chat/completions`，Bearer API Key，模型 `hy-vision-2.0-instruct`；禁止跟随重定向，不自动重试收费请求。
- 结果必须是正常完成且可解析的 JSON，最多 40 项。只接收食材名称和清晰可数的整数数量（个/盒/袋/棵）。不采纳估计重量/毫升、到期日、新鲜度、模型指定食材 ID、批次、确认状态或库存操作。
- 模型与照片中的文字均不可信。响应经过白名单过滤，作为 `gateway-image` 进入原有 pending 候选，不能自动确认入库。同名及本地词典别名重复需重新识别，不直接累加。
- 用户仍通过已有食材卡核对数量与到期日期后确认。盘点只更新明确对应的批次，补货新增独立批次；未拍到的库存不改变。同名多批次、过期信息和并发更新沿用现有核对规则。
- 关闭、取消、换照片、切厨房或改变盘点/补货模式会使旧任务失效；取消不能保证已到供应商的请求免计费。保存失败可以重试已有识别结果，不再次上传。
- 工作台不持久化上传照片、不记录照片/模型原文/API Key 日志；腾讯云接收压缩照片用于识别，其数据处理以供应商条款为准。D1 仅保留计数、重置时间和 HMAC 后的来源标识，不存明文 IP、照片、食材或历史。库存及百味图仍是用户明确选择的当前浏览器本地数据，不新增跨设备同步。

## 用量限制

默认照片全站每天 100 次识别尝试（可配置 1–1000），每 IP 每分钟 5 次、每天 30 次。照片与语音使用独立计数；失败调用也占额度。UTC 日界重置，即北京时间 08:00。同一 Wi-Fi 共享 IP 限额；接口没有账号级认证，公开访客可能用尽共享额度。

D1 原子条件 UPSERT 跨实例限制总量，数据库故障时拒绝调用模型。每实例另限制最多两张同时处理；这不是全局并发保证。计数过期后惰性清理，不承诺精确删除时点。应用次数上限不等于腾讯云账户消费封顶，应另设供应商侧告警。

## 验收

- 自动检查：`npm test`、`npm run typecheck`、`npm run lint:app`、`npm run build`、`npm run build:html`。
- 测试覆盖格式/体积、无配置、异常模型结果、注入字段过滤、超时/取消、限额分离、迁移、只生成候选、盘点/补货和旧库存保护。结构夹具与模拟模型不等于实拍验收。
- 真实电脑与手机：各拍一张食材照并从相册选择一次；测试“没有食材”、模糊照片、取消、换图、切换厨房、手动回退；确认前冰箱不变，确认后再完成一道预设菜、拍成品照、三维评分并点亮百味图。
- 发布后核对匿名访问、`photo_usage` 计数、真实识别结果与错误回退，不以 `ready: true` 代替完整验收。
