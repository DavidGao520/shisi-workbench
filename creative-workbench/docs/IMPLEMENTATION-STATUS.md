### 自动化关键证据

- 连续确认一个包中的多个候选；重复导入 / 确认不加库存；拒绝后重传仍拒绝。
- 元数据矛盾、重复候选 ID、负数、伪造 rawMention 均拒绝。
- “剩饭”数量保持未知；“瓶”保留警告不换算；文件 confirmed 标记不生效。
- 盘点覆盖明确批次、未拍到食材保留；补货只合并相同精确单位和到期信息。
- 固定日期重复推荐十次一致；鸡蛋过敏、缺少锅具、忌口和时间硬过滤。
- 过期批次不计入；另一有效批次仍可用；盒装和模糊数量不假装足量。
- 未人工审校的真实菜谱不能开始；两人步骤中的明确毫升数与食材同步变化。
- 跟做不扣库存；完成才扣；重复完成保持一次；同菜两次只增加历史。
- 完成时 revision 冲突、负数、超量不局部写入。
- fake-indexeddb 连接关闭后重开可读回会话 / 库存；real / demo 分区与重置不互相污染。
- 在 inventory 已排队 put、sessions 即将 put 时注入异常，四个 store 全部回滚。
- 两个连接同时完成同一餐只扣一次。
- 百味图导出转义 script 字样、拒绝未完成会话，不带私人 inventorySnapshot。

## 还不能宣称通过的验收

1. WorkBuddy 指定版本真实加载 Skill，照片 / 已确认文字 → JSON → HTML 确认 → 关闭重开读回。
2. file://、WorkBuddy 内嵌、手机三种承载环境的独立存储、离线重开、权限拒绝和设备兼容性。
3. 真正浏览器里的按钮、触屏、键盘和窄屏 QA。本次没有把 HTTP 200 或 fake-indexeddb 冒充这些测试。
4. 三道现实菜谱的有经验人员审校与实际烹饪。程序里初始 reviews 为空；没有伪造审校姓名或时间。
5. AI 视觉本页直连、语音转写接入、自动文件同步、完整文化事实库 / 12 道菜、整库恢复与模板复刻。
6. 可选 WebMCP 没有受支持的浏览器验证环境；只定义一个打开视图的工具，不读取私人库存或写入，不能包装为 WorkBuddy 自动集成。
