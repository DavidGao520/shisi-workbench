# 食肆工作台 · 评委使用说明

从游戏的一餐到生活的一餐。国宴队将高源与 Jacky 共同创作的《中华食肆》中的菜品、插画与故事，复用为一个非游戏的家庭厨房工作台：识别食材 → 人工核对入库 → 挑选家常菜 → 分步跟做 → 成品照、评分与食忆 → 点亮百味图。

本包以 **评委在自己的 WorkBuddy 中加载随附 Skill，并允许运行配套程序** 为使用前提。无须填写 API Key，也不依赖参赛者电脑或公网网站；照片识别使用评委当前 WorkBuddy 的识图能力与网络。不是双击 HTML 即可使用全部 AI 功能的免安装包。

## 1. 准备与打开（Windows / macOS）

1. **完整解压 ZIP** 到本机可写文件夹，例如 Windows 的 `C:\ShisiWorkbench`，或 macOS 的“文稿/食肆工作台”。不要在压缩包预览里直接运行，不要只取出 HTML；建议避开网盘同步目录和过长路径。
2. 安装并登录 WorkBuddy；准备 **Node.js 22.13 或更新版本**。可从 [Node.js 官网](https://nodejs.org/en/download) 安装；已有可用版本不必重复安装。安装后重开 WorkBuddy / 终端，运行 `node --version` 应显示所需版本。
3. 在 WorkBuddy 中加载本包的 `skills/zhonghua-shisi/SKILL.md`，允许在本包目录读写文件、运行配套程序。可以发送：

   > 请加载这个完整工作台目录里的 skills/zhonghua-shisi/SKILL.md，按里面的流程启动厨房并打开页面。完整目录是：【填写解压后的绝对路径】。

   成功后打开 **http://127.0.0.1:43117/**，能看到“今日一餐 / 我的厨房 / 做菜模式 / 百味图”。Skill 不是自动安装；若当前版本未加载，请按 WorkBuddy 提示完成加载后再继续。

也可双击本包启动文件（启动网页后，照片仍需在已加载 Skill 的 WorkBuddy 对话上传）：

| 操作 | Windows | macOS |
|---|---|---|
| 打开厨房 | `Start-Windows.cmd` | `启动厨房.command` |
| 首次准备麦克风识别 | `Setup-Voice-Windows.cmd` | `初始化语音.command` |
| 停止本地连接 | `Stop-Windows.cmd` | `停止厨房.command` |

启动成功后终端可关闭。停止连接不会删除库存或做菜记录。不要把这个本机地址发给手机或另一台电脑。

## 2. 完整体验一次

**拍照与入库。** 在“我的厨房”先选择家里有的调料；进入“拍照识别”，选择真实/样例厨房及盘点/补货，点击“准备接收照片识别”。随后在**同一个 WorkBuddy 对话**上传食材照片，说“识别这张照片并交回工作台”。回到网页，看到待确认食材，核对数量、单位和到期日期，再确认入库。AI 不判断保质期、新鲜度，也不擅自入库；照片没看清时可重拍或手动补充。

**选菜与跟做。** 从“今日一餐”推荐或“百味图”选择一道菜，查看用料、可展开的“烹饪流程”和“参考文献”。70 道预设做法随时可用；缺少库存记录但实际已备齐的用料可点“确认拥有”，只用于本餐，不额外入库。全部备齐并勾选食材/到期信息/过敏原/厨具核对后开始，按步骤和本步计时跟做，可暂停保存。

**留下一餐。** 完成后可上传成品照，分别评价好吃程度、制作难度、卖相程度；难度为 **1 星困难、5 星简单**。可留一句家庭记忆或下次改进，确认完成后在百味图查看记录。成品照上传不是食材 AI 识别，评分始终由本人填写。

**可选：让 WorkBuddy 另写做法。** 在菜品详情展开对应入口、准备任务，再回 WorkBuddy 说“读取厨房任务，生成做菜步骤”；网页收到草稿后由你核对。没有主动发起这项任务，不影响预设做法。

仅演练界面时用“先逛逛样例厨房”，样例与真实厨房分开；演练不代表实际做过或实拍识别成功。

## 3. 首次启用网页麦克风

本地版语音使用 **Whisper 本机模型**，不是 WorkBuddy 识图，也不调用腾讯云语音密钥。先按 [uv 官方安装说明](https://docs.astral.sh/uv/getting-started/installation/) 安装 uv，重开终端 / WorkBuddy，运行 `uv --version` 确认可用。Windows 可用 `winget install --id=astral-sh.uv -e`；macOS 已有 Homebrew 时可用 `brew install uv`。

然后运行上表的“首次准备麦克风识别”文件。首次需要联网下载 Python、依赖与模型，请提前完成；下载时间取决于网络。Windows 语音路径按 **x64** 环境适配，若提示 DLL 缺失，安装 [微软 Visual C++ x64 运行库](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist) 后重试（[语音依赖的官方要求](https://opennmt.net/CTranslate2/installation.html)）。Windows ARM 语音尚未验收。

看到“语音准备完成”后，刷新本机厨房网页，点“语音录入”，允许麦克风，说“冰箱里有两个鸡蛋、三个西红柿”，结束录音并核对清单。模型保存在本包 `.kitchen-voice/`，准备后本地转写不需联网；音频不保存为文件。初始化不成功时不要当作语音已可用，可先手动输入或体验 WorkBuddy 拍照。

## 4. 常见问题与边界

- **双击打不开 / 提示缺依赖：** 请从本机完整解压的目录运行，按说明安装 Node.js / uv 后重开终端。若脚本被系统安全策略阻止，不关闭全局安全保护；请 WorkBuddy 在授权范围内运行配套 Node 程序，或请设备管理员协助。
- **43117 被占用 / 连不上：** 先在旧工作台目录运行“停止厨房”，再启动这份；不强杀其他进程、不换端口、不清库存。浏览器未自动打开时手动打开上方地址。WorkBuddy 内嵌预览打不开时，用本机 Edge / Chrome 打开同一地址。
- **图片结果没有回来：** 确认网页正在等待，照片发到了加载本包 Skill 的同一 WorkBuddy 对话，并允许它运行脚本。工作目录必须是本包，而不是另一个项目。网页不会自动唤醒 WorkBuddy。
- **语音无响应：** 检查初始化是否成功、浏览器麦克风权限、WorkBuddy / 终端是否已重开。模型下载被网络阻止时应换用允许的网络；不要把缺模型误认为缺 API Key。
- **换电脑后记录不见了：** 库存、成品照、评分在原浏览器本机保存，不随 ZIP 同步。升级时保留原目录和同一浏览器入口，先导出完整备份；当前无整库恢复界面，不要删除旧数据。

照片识别及可选做法依赖 WorkBuddy 账号能力、网络与本机执行权限；只有菜谱、手动闭环和准备后的本机语音可离线使用。菜谱时间与份量为家庭改编估计，参考来源不代表逐道实做认证；实际操作须自行核对熟度、过敏原和厨具。
